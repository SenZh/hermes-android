# 需求分析与目标说明 (Requirements)

## 1. 用户原始需求全文
> "为什么是先下载下来，再让选择目录？不应该是先选择目录，再下载到指定目录吗？还有下载要显示下载进度百分百和速度，文件大小，下载完成后，下载按钮要改成打开文件夹或者打开文件按钮。重新进去这个app也要显示下载已完成，点击打开文件或者文件夹，让用户选择。如果文件夹里面有已存在的同名文件，让用户选择是覆盖还是自动重命名。怎么呈现打开文件或者打开文件夹？按工作流执行，做代码评审和测试用例评审，测试。"

## 2. 可量化验收目标 (Acceptance Criteria)

- [ ] **目标 1：前置目录确认（拒绝流量浪费）**  
  点击下载时，必须先调起目录授权/读取已授权目录；若用户未选择目录或中途取消，立即终止流程，严禁发生任何后台预先下载网络请求。
- [ ] **目标 2：同名冲突弹窗策略**  
  在写入外部目录前，检测目标目录是否存在同名文件。若存在，弹窗提示用户选择【覆盖】或【自动重命名】（自动自增 `(1)`、`(2)`），用户取消则安全终止。
- [ ] **目标 3：流式下载进度、网速与大小双向渲染**  
  下载过程中，界面必须实时显示：
  - 进度百分比（0% ~ 100%）；
  - 已下载字节数与总大小（如 `23.5 MB / 82.0 MB`）；
  - 实时瞬时下载速度（动态换算 `KB/s` 或 `MB/s`）。
- [ ] **目标 4：下载完成状态转换与持久化**  
  下载成功后，大文件卡片与操作栏立即切换为已下载状态，展示【打开文件】与【打开所在目录】双按钮。  
  状态与本地文件 URI 持久化至 `AsyncStorage`，退出并重新进入该页面后，立即检测该文件是否已落盘，若存在且有效则直接呈现【打开文件】与【打开所在目录】。
- [ ] **目标 5：原生调用调起**  
  点击【打开文件】：调用 Android 系统应用（安装器/阅读器）打开文件；  
  点击【打开所在目录】：调用系统文档管理器（DocumentsUI）打开并聚焦到授权的目标文件夹。
- [ ] **目标 6：工程工作流门禁**  
  设计、代码、测试产物经子代理双审闭环，本地 `npm test` 52+ 项测试全绿，方可提交构建。
