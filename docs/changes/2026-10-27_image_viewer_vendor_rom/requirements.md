# 需求：图片手势查看器 + 国产 ROM 文件打开适配

日期：2026-10-27
状态：已实现，待审查

## 背景

上一轮交付的 v1.8.3-preview.22 在真机上有两处失败：

1. 打开图片时无法缩放，用户原话「图片不行，不能缩放」「必须得是一个图片浏览器，能支持双手扩开放大或缩小，能点一下撑满屏，点一下再返回」。
2. 更早的 preview.21 之前，`openFile` 报 `Only local file URLs are supported (expected scheme to be 'file', got 'content://...')`，`openFolder` 弹出「Hermes 想要打开 Google」。

## 需求条目

| ID | 需求 | 验收标准 |
|----|------|---------|
| R1 | 图片支持双指捏合缩放 | 可放大到至少 3x，缩小回 1x，松手不停在模糊中间态 |
| R2 | 图片支持放大后拖动 | 放大状态下单指拖动可看图片四角，不能拖出屏幕只剩黑底 |
| R3 | 单击撑满屏，再单击返回 | 1x 状态下单击进入全屏；全屏内再单击退出 |
| R4 | 打开文件不报 scheme 错误 | 点「打开文件」不出现红色错误 toast |
| R5 | APK 能被系统安装器接管 | 点 APK 的「打开文件」直接进安装界面 |
| R6 | 打开所在目录不弹 Google | 落到文件管理器，不出现跨应用授权弹窗 |
| R7 | 国产 ROM 后台保活有引导入口 | 关于页可查看电池优化状态并跳转自启动设置 |
| R8 | 保持既有下载逻辑不变 | 进度、速度、状态、选目录、冲突处理不回退 |

## 明确不做

- 不引入新的图片库依赖（`react-native-image-viewing` 等），项目已有 gesture-handler + reanimated。
- 不做视频手势（本轮只覆盖 `image/*`）。
- 不实现「自动开启自启动」——Android 无此 API，见 tech-design。

## 约束

- 用户铁律：任何新功能必须先有自动化测试并通过 `npm test` 才允许提交。
- 单测必须真实 `import` 生产代码，禁止在测试文件内自建 mock 逻辑自证。
- 禁止 JS 层对大文件做 base64（会 OOM）。
- 版本号遵循三位 + preview 后缀，公开 Release 只用纯三位。
